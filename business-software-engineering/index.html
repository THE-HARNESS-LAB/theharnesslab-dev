Custom business software engineering from the interface to the final handoff.

A business website, an internal tool and an API integration expose different parts of the same operating process. Design the records, permissions and recovery path alongside the interface.

Separate the public site from the working system

A public website explains the offer and collects a permitted enquiry. An internal tool manages working records and decisions. An integration carries identified changes between systems. These boundaries help define which data is public, which users may act and which effects need confirmation.

For the public site, preserve useful content and navigation in the delivered HTML. Make the enquiry path explicit and handle unavailable JavaScript or an unconfirmed form request. A successful page render does not establish that a lead reached the receiving system.

Define the record before connecting the applications

Identify the source of truth, stable record identifiers, accepted field values, attachments and change history. Specify ownership of each field. A two-way sync needs a conflict rule; timestamp ordering alone may not represent the business decision you need to preserve.

Keep account permissions narrow and separate tenants or client workspaces where required. Public contact information, a customer record and a provider credential should not share the same exposure boundary.

Make integration outcomes inspectable

Repeated events need a defined operation identity. A timeout after dispatch needs reconciliation before a blind retry. Record intent, the attempted destination operation and the receipt separately so an operator can determine the last confirmed effect.

The HTTP specification's discussion of idempotent methods is a useful reference; business-level duplication also depends on the destination API and its operation contract. Our workflow automation notes explore the wider execution model.

Use a model where interpretation is needed

Document classification or a proposed extraction can benefit from AI. Known calculations, required-field validation and permission checks should remain explicit. Preserve the source of a proposed value and keep acceptance separate from the model response.

Landman title research illustrates these concerns: a plausible ownership schedule still needs source instruments, correct tract identity, exact arithmetic and an independently reviewed export.

Verify the artifact and the receiving boundary

Test a representative record from intake through the actual output. Inspect exported workbooks or documents independently where practical. Include missing fields, repeated events, unavailable dependencies and a restart in the acceptance plan. An integration response and a complete business result are different pieces of evidence.
