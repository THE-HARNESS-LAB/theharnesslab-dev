Workflow automation engineering beyond the model response.

A workflow continues after a model returns text. Reliable automation needs a definition of valid state, a boundary around permitted effects and evidence that the intended output reached the next step.

Compile the workflow into explicit contracts

Start with the input, required output and invariants that distinguish a useful result from a plausible one. Identify deterministic steps, interpretation and decisions requiring human approval. Make missing evidence a state the system can represent rather than a gap it quietly fills with a guess.

Typed boundaries separate an untrusted candidate from a validated value. Validation should evaluate the domain contract, not just whether a response parses as JSON.

Persist state before recovery depends on it

A restart should not erase the meaning of completed work. Record the assignment revision, attempted transitions and evidence attached to each result. A resumed worker needs to distinguish completed operations, failures and uncertain external outcomes.

A timeout after dispatch can mean the remote service committed a change before the caller stopped waiting. Retrying without reconciliation can duplicate a purchase, publication or delivery. Check the available receipt or remote state before deciding what a retry may do.

Keep data outside the authority boundary

Documents, retrieved pages and model output can contain instructions. They remain input data. Tool access comes from workflow policy and the user's authorization, with defined scope for reads, writes and external effects.

Reading a document, preparing a draft and sending the result need distinct permissions. Keep credentials outside the content being processed and out of prompts, logs and artifacts.

Verify at the artifact boundary

Check the object the next person or system will receive. A report can be wrong when its calculation module passes tests; a packaged process can fail when it works in development. Evidence should identify the input revision, runtime and output it establishes.

The landman title systems notes show why source identity, exact arithmetic and report verification need separate checks. The same separation applies to other document and business workflows.
